## 📌 简介

StarGate 是 TAI Research 为 GTC 系列模型打造的**专家级基准测试**。

它不测模型能不能聊天，测的是**模型在真正困难的问题上能不能算对**：研究生水平的数学与物理、需要推理链的化学与生物、算法分析、形式逻辑、以及必须准确记忆的古文。

**每一题都只有一个可辩护的答案**，判分是精确匹配，没有部分分。一个听起来合理但错误的回答得零分。

---

## 🎯 设计原则

| 原则 | 说明 |
|------|------|
| **唯一答案** | 每题都有一个专家能得出的确定答案，且可机器判分 |
| **拒绝模式匹配** | 数字和情境经过选择，答案不能靠背诵常见题面得到 |
| **难度来自内容** | 靠材料的深度，不靠刁钻的措辞 |
| **不奖励啰嗦** | 每題规定答案长度，冗长不得分，简洁也不扣分 |

### 为什么不用「禁止关键词」这类设计

早期版本用过「列举中国城市时禁止出现北京」这种检查。**那是在惩罚正确答案** —— 一个老实作答的模型必然写出北京，只有刻意绕开最该说的那个词的模型才能通过。那不是评测能力，那是评测谁更会猜出题人的心思。

新版本里，**任何检查失败都只因为模型答错了**，绝不可能因为答得太标准。

## 🚀 快速开始

### 1. 运行评测

```bash
python3 run_stargate.py \
    --cases stargate_cases.jsonl \
    --model tfmf \
    --api http://127.0.0.1:5001 \
    --key "$TAI_API_KEY" \
    --temperature 0 \
    --out results.json
```

### 2. 为什么必须用 `--temperature 0`

**默认温度下同一个模型同一套题会跑出不同的分数。** 实测过：温度 0.7 时连续两次得到 75.6% 和 85.4%，其中「逻辑推理」一项从 3/10 摆到 6/10。

```
temperature=0.0   两次逐科完全一致   ← 可以引用
temperature=0.7   75.6% → 85.4%     ← 不能引用
```

**要对外公布分数，就必须用 0。**

## ➕ 如何添加新用例

在 `stargate_cases.jsonl` 末尾追加一行：

```json
{"id": "MA-007", "category": "mathematics", "user": "求 2^100 的末两位数字。只回答数字。", "expected_answer": "76", "max_new_tokens": 1024}
```

### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 唯一标识 |
| `category` | string | 所属科目 |
| `user` | string | 题面 |
| `expected_answer` | string | 答案必须包含的内容（精确匹配，已处理下标和全角） |
| `expected_keywords` | list | 必须出现的关键词；元素可为列表表示**同义可选** |
| `must_match` | list | 必须匹配的正则 |
| `must_not_match` | list | 不得匹配的正则 |
| `min_distinct_lines` | int | 至少要有多少行不重复的内容 |
| `min_new_tokens` | int | 答案最短长度 |
| `max_chars` | int | 答案最长长度 |
| `max_repeat_ratio` | float | 去重率下限，用于检测复读退化 |
| `max_new_tokens` | int | 最大生成长度 |

### 出题时请注意

1. **先自己把题算一遍。** 出题人算错答案，测的就是出题人。
2. **检查要接受所有正确答案。** `还` 和 `而且` 都是对的（用同义列表）；`H₂O` 和 `H2O` 是同一个答案（已归一化）。
3. **不要用「禁止标准答案」做难度。**
